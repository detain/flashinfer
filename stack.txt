# WHY THIS STACK EXISTS
#
# sglang's QSA (Qwen Sparse Attention) index-K scoring currently packs the
# compressed-K rows into a contiguous ragged buffer before scoring them, with a
# fused packer kernel, a per-forward scratch buffer and a host readback to size
# it. flashinfer PR #4899 adds a scorer that reads the PAGED compressed-K cache
# directly, which makes that packing unnecessary.
#
# The sglang-side integration is NOT built. It is planned in
#   /root/sglang/sglang.prev/plan_flashinfer_paged_index_k_scorer.md
# and is gated on #4899 landing in a flashinfer RELEASE. This stack exists so
# the scorer can be developed and tested against locally before that happens.
#
# IMPORTANT: #4899 is OPEN upstream, not merged. It is cherry-picked with
# `git cherry-pick -x`, so each commit carries its origin hash.

WHAT IT ADDS
==============================================================================

  flashinfer.sparse_paged_scores(
      q,                    # [rows, num_heads<=16, head_dim] bf16|fp16
                            #   head_dim in {64,128,192,256}
      k_cache,              # [pages, page_size, head_dim], SAME dtype as q
                            #   note: NO kv-heads dimension
      page_table,           # [num_requests, width]; NEGATIVE entry = unmapped,
                            #   which scores as -inf
      token_to_req,         # [rows]; NEGATIVE = empty (masked) query row
      query_positions,      # [rows] int32, position of each query in its request
      sequence_lengths,     # [num_requests] int32
      compress_ratio,       # a query scores only entries FULLY behind it:
                            #   visible = (pos + 1) // ratio
      divisor,              # score scale (sglang passes sqrt(head_dim))
      num_columns=None,     # optional column cap
      logits=None,          # caller-provided fp32 [rows, width*page_size]
      visible_blocks=None,  # caller-provided per-row scored count
  ) -> (logits, visible_blocks)

  Score function: logits[r,c] = sum_h max(0, dot(K[c], Q[r,h])) / divisor
  -- exactly sglang's QSA relu-MQA logits.

INSTALL (isolated -- does NOT touch the live server's flashinfer)
==============================================================================

  The production sglang venv (/root/sglang/.venv) keeps flashinfer 0.6.18,
  which is what the running server imports. This stack is 0.7.0-dev and is
  installed in a SEPARATE venv that overlays the production one read-only:

    python -m venv /root/sglang/.venv-fi4899
    SP=/root/sglang/.venv-fi4899/lib/python3.12/site-packages
    # dev tree FIRST, production site-packages LAST (deps only)
    echo /root/sglang/flashinfer                              > $SP/00_flashinfer_dev.pth
    echo /root/sglang/.venv/lib/python3.12/site-packages      > $SP/zz_overlay_prod.pth
    /root/sglang/.venv-fi4899/bin/python -m pip install \
        -e /root/sglang/flashinfer --no-deps --no-build-isolation

  BUILD_NVEP=0 BUILD_NIXL_EP=0 BUILD_NCCL_EP=0 FLASHINFER_AOT=0 were set; the
  moe_ep/NIXL native build is irrelevant to the scorer and nccl-extensions is
  not installed in the production venv.

  WHY THE TWO .pth FILES ARE ORDERED THAT WAY -- setuptools APPENDS its
  editable finder to sys.meta_path, so it runs AFTER the default path finder.
  With only the overlay .pth, the default finder resolved the top-level
  `flashinfer` package to the production 0.6.18 directory while the editable
  finder still served `flashinfer.sparse_scores` from this tree -- a 0.6.18
  package with 0.7.0 submodules grafted on. 00_flashinfer_dev.pth sorts first
  and puts this tree ahead of production on sys.path, so the whole package
  resolves consistently from here. If you rebuild the venv, keep that order.

  Verify:
    /root/sglang/.venv-fi4899/bin/python -c \
      "import flashinfer; print(flashinfer.__version__, flashinfer.__file__, \
       hasattr(flashinfer,'sparse_paged_scores'))"
    # -> 0.7.0 /root/sglang/flashinfer/flashinfer/__init__.py True
    /root/sglang/.venv/bin/python -c \
      "import flashinfer; print(flashinfer.__version__, \
       hasattr(flashinfer,'sparse_paged_scores'))"
    # -> 0.6.18 False      (production venv, must stay this way)

  RUN BOTH FROM A NEUTRAL DIRECTORY (e.g. cd /root). Python puts the cwd on
  sys.path[0], and /root/sglang/flashinfer contains a real `flashinfer/`
  package, so running the checks from the repo root makes the PRODUCTION venv
  report 0.7.0 with the scorer present -- which looks exactly like the thing
  this isolation is meant to prevent. It is an artifact of the cwd, not a
  contaminated venv. The authoritative on-disk check is:
    ls -d /root/sglang/.venv/lib/python3.12/site-packages/flashinfer_python-*.dist-info
    # -> flashinfer_python-0.6.18.dist-info

==============================================================================
KNOWN GAPS AND TRAPS
==============================================================================

  * SUBMODULES WERE NOT INITIALIZED in this clone (now FIXED, see below).
    3rdparty/{cccl,cutlass,spdlog,nixl} were all empty, so the first JIT
    compile of the scorer failed in include/flashinfer/fastdiv.cuh:39 on
    `cuda::fast_mod_div<uint32_t>` -- the build had fallen back to CUDA 12.9's
    bundled libcu++, which does not have it. fastdiv.cuh is byte-identical to
    upstream/main and is NOT touched by #4899, so this was a checkout-setup
    problem, not a PR defect.
    Resolved by initializing cccl, cutlass and spdlog at their pinned SHAs
    (16bd510c / b46b16d0 / c3aed4b6). nixl is still empty -- it is the
    moe_ep transport and is not needed for the scorer.
    TRAP: `git submodule update --init --depth 1` does NOT work here. A shallow
    clone cannot reach the pinned commits, and it leaves a shallow repo behind
    that makes every later attempt fail the same way ("Fetched in submodule
    path ..., but it did not contain <sha>"). Recovering needs an explicit
    `git -C .git/modules/3rdparty/<name> fetch --unshallow` first. Clone full.
  * Local nvcc is 12.9; the repo's ci/cuda-versions.json carries both cu129 and
    cu13x runtimes, and the venv's torch is 2.13.0+cu130. Mixed-major setups
    are a known source of libcudart conflicts (requirements.txt says so at
    length). Treat any build result here as specific to this machine.
  * `flashinfer.sparse` is a real MODULE in 0.6.18. An availability probe of
    the form `importlib.import_module("flashinfer.sparse.scores")` therefore
    fails on every version and proves nothing. The wrapper is
    flashinfer/sparse_scores.py (top level), and the correct probe is
    `hasattr(flashinfer, "sparse_paged_scores")`.
  * Untouched columns in a caller-provided `logits` buffer are NOT set to -inf;
    an auto-allocated buffer is torch.empty. Consumers must bound themselves by
    the returned `visible_blocks`.
  * #4899 takes fp16/bf16 operands only. sglang's fp8 indexer path cannot use
    it and must keep its existing scorer.
  * Companion PRs #4897 (pre-indexer), #4898 (route kernels) and #4900 (NVFP4
    block-sparse) are all still OPEN and are NOT in this stack. #4899 does not
    depend on them -- it branched off plain main, not off #4897.
